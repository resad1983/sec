AI 正在顛覆軟體產品的底層邏輯。當 Agent 取代人類成為主要使用者，產品的設計語言從互動轉向協議、功能模組重構為任務單元、Skill 成為能力分發新載體。

**用戶不再是人**

一直以來，人們預設產品是給人使用的。現在越來越多產品被 Agent 呼叫，Agent 讀 API、傳參數、拿結果、判斷下一步，它不需要看見介面。

「人的角色從操作者變成了委託者」，產品設計需從幫助人操作轉向幫助人委託。曾經優秀產品需讓用戶看得懂、找得到、點得動，而今「Agent-readable 在變成和 user-friendly 同等重要的產品標準」。

介面也隨之改變。「介面從操作台變成了監控台」，幫人看見 Agent 進展、哪裡需確認、哪裡可回滾。傳統 API 是動作級的，未來則是任務級介面——prepare_customer_meeting、summarize_contract_risk 等，一個介面完成一整件事。

「軟體給人用時體驗是路徑，給 Agent 用時體驗是協議」。當通用 Agent 在後台替用戶挑選呼叫各種工具軟體，很多公司會失去直接用戶關係。「Agent 入口可能讓 SaaS 失去前台關係」。

**開發，不再圍繞功能**

以往產品經理絕大多數時間在加功能。現在需要定義任務節點、什麼時候呼叫工具、什麼時候算交付完成。

功能點開發反映系統能做什麼，「基於任務的開發則是回應要完成什麼」。完成客戶會前準備，涉及日曆查詢、郵件檢索、CRM 資料、摘要生成、文件排版，跨多個傳統功能模組。

「Skill 會成為流程的最小可復用單元」。一個 Skill 是可遷移的做事方法，Agent 產品價值在於什麼時候呼叫、呼叫後怎麼判斷、失敗怎麼辦。「Memory 會成為長期差異化來源」，系統積累的用戶上下文、專案歷史、組織規則難以搬走。

**方法的產品化**

「通過 Skill，方法本身可以產品化了」。顧問公司方法論、律師審查框架、編輯改稿流程都可變成 Skill 分發。

現在是 SaaS（Software as a Service）；未來則是「SaaS，Service as a Software，服務業的軟體化」。「Skill 加上 Memory 才能從通用能力變成個人能力」。加上 Eval 才能持續進化，檢查是否符合格式、遺漏關鍵資訊。

產品進化從功能增加變成能力成長，從 Feature Roadmap 到 Capability Roadmap。驗證方式也變了，從 MVP 到「MVT，Minimum Viable Task」。
