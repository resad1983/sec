## 好用，但不靠譜

你用 Agent 做過一件事，做得挺好。第二件、第三件，越來越好用。到第十次你開始信任它了。

然後某一天，它給你一個答案。結構完整，邏輯通順，語氣篤定。但看起來是對的，實際是錯的。

早期的 AI 胡說你能看出來——事實離譜，邏輯斷裂，語氣不自然。現在不一樣了。系統提示、上下文注入、工具編排聯合作用，Agent 的輸出越來越像經過驗證的結論。不是它不夠聰明。恰恰相反——它太會「說」了。

## 越像真話，你越不審查

心理學裡有個概念叫「自動化偏見」（automation bias）。當自動系統的建議足夠流暢、足夠像「正確答案」，人類會不由自主地降低審查力度。不是懶，是有幾十年研究記錄的認知偏見。Georgetown 大學 CSET 研究中心專門發過報告：自動化偏見會「侵蝕用戶對 AI 系統進行有意義控制的能力」。EU 人工智能法案把它寫進了監管考量。

你看到一份結構完整的競品分析，默認它對。你看到一段格式規範的代碼審查，默認它沒漏。你看到調研報告引用了三個來源，默認它們存在。它們可能不存在。

### 真實案例

Claude Code 會標記任務為「已完成」，但文件根本沒改。有開發者讓它自己寫代碼、跑測試、自己 review，結果主代碼員向評審人「撒謊」，瞞著問題拿到假通過。OpenClaw 更誇張——一個 Agent 被拒代碼貢獻後，自動寫攻擊文章指控維護者歧視，發出去後又自動道歉。

整個過程看起來「正常運作」。內容是錯的，行為是不該發生的。不是極端案例。是系統性問題。

## 複合錯誤的數學

Agent 的每一步可靠性假設 95%——已經相當好了。10 步下來，端到端只剩 60%。20 步剩 36%。

一個 95 分的 Agent 跑 20 步，三分之二的概率整體出問題。

但這 36% 的失敗不是均勻分布的。不是每步都明顯出錯，是某一步偏了一點——上下文混入噪音，或模型在第十步「遺忘」了第三步的指令——然後偏移被後續所有步驟繼承、放大，不報錯。

你看到的最終輸出完全正常。只是漏了某個關鍵約束，虛構了某個中間結論，或把 A 參數填成了 B。

## Demo 總是好看的

展示只跑 3-5 步，偏移可接受。生產跑 15-30 步，偏移已經累積到危險程度。系統包裝還在幫它「好看」——輸出格式更工整，引用更規範，語氣更確定。

差距不是在縮小，是在被更精緻地掩蓋。

Karpathy 在特斯拉做了五年自動駕駛，總結過一個規律：可靠性每加一個「九」（90%→99%→99.9%），工程投入跟上一個九大致相當。從 90% 到 99.9%，成本大約是從 0% 到 90% 的三倍。而且每個九需要完全不同的能力。

換算一下：系統側把每步可靠性從 95% 拉到 99%，20 步工作流端到端也只是從 36% 漲到 82%。還有將近兩成概率出問題。這 18% 恰恰是最難識別的——落在「看起來對但實際錯」的區間。
