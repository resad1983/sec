## 嘉賓背景

**周亦庄**：阶跃星辰退居二線的 LLM 算法工程師，曾負責千億參數語言模型及萬億參數稀疏模型預訓練。高強度 Codex 用戶，試圖用 Agent 改造組織生產工作流程。

## 核心觀點

**2026 是 Multi-Agent 元年**：隨著 GPT-5.2 等模型突破，Agent 能力已達可用水平；2026 年 Skills 的沉澱將推動 Multi-Agent 真正落地。

**AGI 可能在 3 年內到來**（預測：2028 年）。

## AGI 五步路線圖

| 步驟 | 名稱 | 現狀 |
|------|------|------|
| 1 | Chatbot | ✅ 2023 年完成 |
| 2 | Reasoner | ✅ 2024 年 o1 模型 |
| 3 | **Agent** | 🔄 **目前所在位置** |
| 4 | Innovator | 3年內 |
| 5 | Organizer | 3年內 |

## Skills 的本質：壓縮

**MCP vs Skills 的區別**：
- MCP：Agent 與 API 的互動接口
- **Skills**：把成功的工作流/實踐壓縮成可複用的人類驗證經驗

> 「《孫子兵法》中『知己知彼，百戰不殆』這八個字，實際是人類在社會演化過程中總結出的 Skills。」

**Skills 的產生過程**：
1. Agent 接受任務，多次嘗試，繞了很大的圈子
2. 任務完成後，人類確認「你做的非常好」
3. 要求 Agent 把探索過程記錄下來，下次不犯重複錯誤
4. 這段記錄 = Skills（被人類驗證過的成功實踐）

## Scaling 三階段演進

1. 參數擴展（更大的模型）
2. **推理強化**（o1 系列，長思維鏈）
3. **工具交互**（Agent 與現實世界/API 的連結）→ 現在所在位置

## Multi-Agent 為何需要「組織架構」

- 單 Agent 難以持久運行 → 需要分工協作
- 借鑒人類管理工具（如 OKR），讓 Agent 通過信息流協同工作
- 最簡單的模型：一個 leader（任務編排者/調度者）+ 一群 executor
- Leader 只發號施令、接收反饋，**不具體執行任務**

## Innovator 與 Organizer（第四、五步）

**Innovator**：
- 需要能力的深度 + 觸手的廣度
- 「能調動現實世界的資源為自己的假設買單」
- 不只是會寫代碼，而是能作為獨立個體做實驗驗證猜想

**Organizer**：
- 基於 high-level 願景，把各種 Agent 搓合在一起
- 調動資源、做更複雜分析，最終實現科學突破
- Innovator 和 Organizer 是正交的過程，「你中有我，我中有你」

## 個人工作流轉型

> 「我從年底開始到1月，整整一個月沒有寫過任何一行代碼，也沒有敲過任何一個命令。全都是通過和 Agent 的對話來完成我的日常工作。」——周亦庄

關鍵機制：讓模型持續更新自己的 memory，從自己的工作中反復學習。
