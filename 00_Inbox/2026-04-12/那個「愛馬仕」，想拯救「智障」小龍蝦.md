4月初，Hermes Agent 火了。它由 Nous Research 在 2 月發布，定位是「The agent that grows with you」。核心賣點是一個閉環學習系統：Agent 完成複雜任務後，自動把經驗固化成 Skill，下次遇到類似任務直接複用，還能在使用過程中持續改進。

但這個敘事遮蔽了一個更基本的問題：Skill 真的是當前 Agent 落地的主要瓶頸嗎？

## Skill 很性感，但它可能不是最重要的問題

一個容易被忽略的事實是：目前公認體驗最好的編程 Agent 產品之一——Claude Code，它好用的基石並不是 Skill 的自動進化，而是背後大量扎實的 CLI 工具支撐。

用 GlobTool 找候選文件，用 GrepTool 定位相關代碼片段，用 FileReadTool 查看實現細節，用 LSPTool 做代碼符號跳轉和引用分析。每一個都是確定性的、零 token 消耗的原子操作。

CLI 不性感，不好講故事，但它才是 Agent 能力的真正地基。

## 龍蝦最被人詬病的地方，Skill 自主進化解決不了

OpenClaw（俗稱「龍蝦」）最被人詬病的兩點：一是 token 消耗大、帳單吃不消，二是長時間工作穩定性差、經常失聯。

往下拆，會發現它們經常來自同一個源頭：Agent 在用劣質工具——比如脆弱的瀏覽器自動化——去完成本該由確定性工具完成的任務。

工具越脆弱，試錯越多；試錯越多，token 燒得越快；任務鏈越長，失聯和中斷的概率也越高。

Skill 自主進化解決的是「怎麼更聰明地使用一個工具」，但並沒有解決「好工具本身稀缺」的問題。Skill 可以讓 Agent 更熟練地駕馭一匹跛腳馬，但並不能把跛腳馬變成千里馬。

## 下一個真正的戰場，在 CLI 層

Hermes 和 OpenClaw 的選型對比，本質上是一個「敘事性 vs. 基礎設施性」的選擇。
