*2026年5月20日 07:57*

本文來自微信公眾號：衛夕指北，作者：衛夕，題圖來自：AI生成

先說明一點，我並不是要挑起Windows和Mac的對立，這篇文章我只講事實和邏輯。

數據就是數據，趨勢就是趨勢。

咱們從一個事實開始：

微軟是 OpenAI 最大的股東，往裡砸了超過 130 億美金，CEO Satya Nadella逢人就講 AI。

然而，如果你今天去問一個真正在用 AI 工具寫代碼、搞生產力的開發者，他大概率沒有在用 Windows。

Claude Code、Codex CLI等編程工具跑在哪裡？

在終端（Terminal）裡。

沒錯，去年冬天之前，我甚至不知道Mac裡還有終端這個東西。
但今天我已經可以熟練地用終端裡的Claude Code給一個硬體寫一個映射軟件了。

我用 Windows 的時間比用 Mac 長（曾經用了很長時間的Surface），對微軟的產品也沒什麼成見。
但上面這些操作我在Windows裡整了很久都沒有搞定。

沒錯，一個事實就是：
對於AI Coding而言，macOS 和 Linux 是一等公民，而 Windows 是需要額外折騰的二等公民。

下面細說邏輯。

### 一 為什麼 AI 時代的開發工具，天然偏向 Unix 系

我們來看一個邏輯：為什麼 AI 時代的開發工具，天然偏向 Unix 系。

這些工具的工作方式是：在你的終端裡啟動一個 Agent。
這個 Agent 會讀你的整個代碼倉庫，然後自己規劃多文件修改，寫代碼，跑測試。
整個過程中，它需要執行 shell 命令，操作 git，調 Docker，安裝依賴。

這一整套工作流，在 macOS 和 Linux 上是原生的，這兩個操作系統是 Unix 的血統。

然而，到了 Windows 上：
- 路徑分隔符是反斜杠，和全世界所有 URL、所有 Unix 路徑的正斜杠反著來，語法和 Bash 差異很大。
- 大量開源工具的 README 默認給你寫的是 Bash 命令，隱含假設你在 Unix 環境下。
- npm install 在 Windows 原生文件系統上的速度，確實非常慢。這話不是我說的，微軟自己在 2026 年 3 月的 WSL 改進公告中，以這個痛點作為開篇來論證為什麼要改進 WSL。

那麼問題來了——微軟給出的解決方案是什麼？
WSL——Windows Subsystem for Linux。
就是在 Windows 裡面跑一個 Linux 虛擬內核。

你買了一台 Windows 電腦，為了用上 AI 開發工具，你得在 Windows 裡裝一個 Linux。
能跑嗎？能。
離譜嗎？離譜。

### 二 跨文件系統操作的「WSL 稅」

有人會說，WSL 已經很成熟了。
2026 年的 WSL 和當年不可同日而語，開機不到兩秒，資源動態分配，文件系統互通。
技術上這話沒毛病。

但魔鬼藏在邊界裡。
我們說一個很具體的場景：跨文件系統操作。

一個四五人的開發團隊，有人用 VS Code 在 Windows 側編輯，有人在 WSL 裡跑 Agent，有人用 GitHub Desktop 在原生 Windows 上做 code review。
兩套文件系統之間的狀態同步，就變成了一個持續的噩夢。

BaristaLabs 在 2026 年 3 月的實測報告裡指出：
在 WSL 環境中跑 AI 編程 Agent 的團隊，有 15% 到 20% 的 Agent 輔助開發時間，花在調試環境差異產生的 bug 上。

微軟多年前的回旋鏢，今天開始正中眉心。

OpenAI 的 Codex CLI 官方安裝指南說得很明確：這個工具是為 Unix-first 環境建置的（built for Unix-first environments）。
直到 2026 年 3 月 4 日，OpenAI 才終於給 Codex 出了一個原生 Windows 版本，用 PowerShell 和原生 Windows 沙箱跑。

BaristaLabs 發了一篇博客，標題是：WSL 稅沒了（The WSL Tax Is Gone）。
一個稅字就足以說明一切。
之前在 Windows 上做 AI 開發，是要交稅的。
而在 macOS 和 Linux 上，這個稅從來就不存在。

### 三 開源 AI 生態的 Unix 基因

再看開源 AI 生態的 Unix 基因。
2026 年 AI 領域最重要的開源基礎設施項目：
PyTorch、Hugging Face Transformers、llama.cpp、vLLM、Ollama、MLX、DeepSpeed、Ray。

幾乎無一例外地誕生於 Unix 環境，由 Unix/Linux 開發者社區維護。
翻開這些項目的安裝文檔，示例命令清一色是 Bash 語法。

Windows 用戶要跑這些東西，傳統上要裝 WSL，或者裝 Anaconda 試圖抹平差異。
AI 開發的整個技術棧，從模型訓練框架到推理引擎到部署工具，都是在 Unix 土壤裡長出來的。
macOS 因為自身的 Unix 血統，天然就是這個生態的一部分。
Windows 則是外來者，需要一層翻譯（WSL）才能融入。
而且這個格局在可預見的未來很難改變。

### 四 統一內存架構（UMA）的硬體降維打擊

講完軟件講硬體。
AI 時代的本地推理能力，蘋果的晶片 Apple Silicon 幾乎是降維打擊。

這裡核心就一條：統一內存。
傳統 PC 的架構是 CPU 有自己的系統內存，GPU 有自己的顯存，兩個內存池物理隔離，互不相通。
當你想在本地跑一個 AI 模型的時候，模型的權重必須完整裝進 GPU 顯存才能獲得 GPU 加速推理。

蘋果的M系列晶片在統一內存架構（UMA）下，CPU、GPU共享同一個物理內存池。
你配了 64GB 內存，GPU 可以完整使用全部 64GB。
一台 MacBook Pro M4 Max 64GB，可以原生加載並運行一個約 70B 參數模型（約 42GB）。

在 Windows PC 上，你需要一塊價值 6000 美元以上的專業顯卡才能做到這件事，而且這種配置在消費市場上很難找到。

Compute Market 在 2026 年 3 月的評測提供了一組很說明問題的數據：
Mac Mini M4 Pro 售價 1399 美元，要組裝一台同等 AI 推理能力的 RTX 4090 台式機，你需要 GPU、CPU、主板、內存、電源、機箱、散熱器、存儲，總價 2800 到 3500 美元。
這個差距是非常現實的。

### 五 冷啟動發行優先的 Mac 效應

有人說我不是開發者，我只是一個普通的AI用戶，那這兩個平台差別就沒那麼大吧？
錯了！

我們來看一些事實：
- 2024 年 5 月 13 日，OpenAI 發布 ChatGPT 桌面客戶端——只有 macOS 版本。Windows 版要等到年底。
- Claude 桌面應用 2026 年 3 月 24 日 Computer Use上線，macOS 先發，Windows 版 4 月 3 日才到，晚了10 天。
- Google 的 Gemini 原生桌面應用今年 4 月 15 日上線——首發平台，macOS。Windows 版截至 5 月還沒有。
- Perplexity 今年的殺手級產品 Personal Computer 是 macOS 獨佔，Windows 版沒有時間表。
- Ollama 的桌面應用在 2025 年中期上線時也是 macOS 先發。

這個名單還可以繼續拉下去，但意思已經很清楚了。
這波 Mac 優先，本質上並非蘋果贏了 Windows 的市場份額，而是蘋果贏了 AI 產品的冷啟動環境。

Windows 仍然是辦公世界的主幹道，但 AI Agent 的第一批種子用戶，很多在 Mac 上：程序員、創作者、獨立開發者、AI 重度用戶、矽谷創業團隊。
這群人不一定人數最多，但他們最愛折騰，最能把產品吹爆，也最容易把一個新 Agent 送上 Product Hunt、X、Hacker News。

換句話說，Mac 在 AI Agent 時代的價值，並非裝機量第一，其實是擴散效率第一。

### 六 地緣開發者的生態偏向

再說一下這背後一個顯而易見的原因：
AI 時代最重要的工具，比如Claude Code、ChatGPT、Cursor、Codex CLI、Ollama、Hugging Face 的各種庫，是誰打造的？
絕大多數是舊金山灣區和矽谷的團隊。

而舊金山和矽谷的開發者群體，是全世界 Mac 滲透率最高的地方，甚至沒有之一。
這些 AI 工具的創造者，自己每天用的就是 Mac。
這意味著他們開發和測試的第一環境就是 macOS。
他們在 Mac 上自己寫的命令行工具，天然會讓它在 macOS 上跑得最順暢。
Windows 支持？那是下個季度的OKR。

這其實是產品開發中樸素的邏輯：你在哪個平台上開發，你就先讓產品在哪個平台上好用。

### 七 系統層 AI 支持的面子與裡子

有人說，MacOS系統本身的AI支持很少，Windows 在系統層AI功能做了很多努力。
這句話大體上沒錯。

但如果你仔細用了Windows系統的AI功能的話，你會發現它其實有非常多翻車的地方。
微軟把 Copilot 按鈕硬塞進 Windows 11 每一個角落的操作——記事本、畫圖、照片、截圖工具、文件管理器、設置，無一倖免。
記事本右上角那個彩色 Copilot logo，已經成了 Windows 社區的嘲笑梗。

很明顯，這麼搞用戶是會有反彈的。
2026 年 3 月 20 日，TechCrunch 報道微軟開始回撤 Copilot 的功能膨脹。
截圖工具和照片應用裡的 Ask Copilot 按鈕被移除了。記事本的 AI 功能被改名為更低調的 Writing Tools。
Windows Central 的消息源說微軟已經暫停了在更多系統應用中添加 Copilot 按鈕的計劃。
微軟甚至已經把 Copilot 從 Xbox 上撤了。

微軟選了一條路：在系統界面上做 AI 的面子。
Apple 選了另一條路：在底層硬體和框架上做 AI 的裡子。

### 八 雲計算與本地推理的隱秘利益衝突

再講一個大多數行業觀察者不太會注意到的結構性矛盾。

微軟同時扮演著兩個角色：全球最大的雲端運算 AI 基礎設施供應商（Azure + OpenAI），以及全球最大的桌面操作系統製造商（Windows）。
你乍一看覺得這兩者是協同的，仔細一琢磨會發現，它們之間存在一個隱秘的利益衝突。

Azure 的商業邏輯是：你本地幹不了的事越多，你就越依賴我的雲。
你需要訓練大模型？來 Azure。你需要部署 AI 應用？來 Azure。
微軟 2026 財年在 AI 相關基礎設施上的資本開支已經接近 800 億美元量級。
這個賭注，賭的就是未來的算力會繼續往雲端集中。

那麼問題來了：如果微軟真的把 Windows 做成了一個本地 AI 的優秀平台，豈不是在自己的雲業務膝蓋上捅了一刀？
微軟做不到自洽。

### 九 份額大盤與擴散趨勢

上面說了這麼多結構性的劣勢，一個自然的追問是：這些劣勢到底有沒有反映在市場份額上？

先看大盤。
StatCounter 2026 年 4 月的數據，全球桌面操作系統市場份額：Windows 63.6%，macOS 加上舊版 OS X 合計約 12.6%，Linux 3%，ChromeOS 1.5%。
Windows 依然是絕對的老大，這個沒有爭議。

但趨勢比存量數據重要得多。
IDC 的出貨量數據顯示：
- 2025 年第三季度，預裝 macOS 的設備出貨量同比增長了 14.9%，而同期全球 PC 出貨量僅增長 8.1%。
- 再往前，2025 年第二季度，Mac 出貨量增長 21.4%，全球 PC 增長 6.5%。
- 第一季度，Mac 增長 7%，全球 PC 增長 4.8%。連續三個季度，Mac 的增速都是整體市場的兩倍到三倍。

更關鍵的是地域結構：在美國市場，macOS 的份額遠高於全球平均水平：2025 年初已經達到 28.5%，幾乎是全球佔比兩倍。
而美國恰恰是全球 AI 產業的核心地帶，是 AI 工具創造者和早期採用者集中的地方。

蘋果為了主動加速，在 2026 年 3 月 4 日發布了 MacBook Neo。
這是蘋果有史以來對入門級筆記本市場發起的最激進攻擊。起售價 599 美元（國內到手約 3399 元）。
庫克將價格砍掉了 40%，但硬體上配備了 A18 Pro 晶片、台積電 N3E 工藝、200 億晶體管、續航長達 16 小時，且跑完整的 macOS。
MacBook Neo 將大批此前被價格擋在門外的學生、入門用戶拉入生態，一旦進來，便會發現 macOS 上的 AI 生態更為順暢。

### 十 結語

必須要說明的是：我不是在說 Windows 完蛋了。
在企業 IT 管理、.NET 和 Azure 生態裡，Windows 依然 YYDS。全球市場份額超過 60%，基本盤短期內無人能撼動。

但生產力的定義變了。
今天，AI Agent 成為新的生產力單元、終端取代圖形介面成為人機協作方式、本地推理能力成為選硬體的關鍵指標。
Windows 在這三個維度上都不是最優解，目前也看不到短期拐點。

在 AI 這個新戰場上，先手優勢正在快速向 Unix 系的對手傾斜。
微軟會如何反擊？我們拭目以待。
