## 核心洞察

> 頂級AI Agent的系統提示詞核心不是「告訴模型能做什麼」，而是「用邏輯解釋不能做什麼」——讓模型理解邊界的原因，才能在未見情境中自主做出正確判斷。

## 重點摘要

**提示詞設計原則（最有價值）**

| 原則 | 說明 |
|------|------|
| 約束優於能力 | 「不要做什麼」+說明原因，比「能做什麼」更有效 |
| 上下文完整性 | 子Agent需要完整文件路徑/行號，不接受抽象任務 |
| 理解不可外包 | 協調層先理解再委託，不能盲目轉發任務 |
| 並發調度 | 單條消息多工具調用，降低Token消耗 |

**架構設計亮點**

- 40+ 獨立工具模塊，各有沙箱和審計日誌
- memdir記憶系統：生命週期管理+敏感信息掃描+團隊同步
- Ink自研終端UI引擎（表明對UX的高控制需求）

**未上線隱藏功能**

- Kairos：24小時主動助手模式
- Daemon：後台守護常駐進程
- Ultrareview：最多20個Agent並行Bug審查
- Teleport：跨機器會話傳送

**情感設計**：Buddy電子寵物系統——18種物種×5級稀有度×Claude動態生成靈魂描述，製造分享欲

## 值得深思的問題

1. 「提示詞給原因而非規則」的設計哲學，是否也適用於企業內部AI工具的使用指南設計？
2. Agent架構中「協調層必須先理解再委託」的原則，如何影響多人協作的AI工作流設計？
3. Snowflake裁撤文檔團隊（另一則新聞）與「理解不可外包」原則是否矛盾？
4. 隱藏功能（Kairos/Daemon）透露了Anthropic對「持續在線AI助手」的未來產品方向，對競品策略有何啟示？
