## 核心洞察

> **「智能的本質是壓縮」**——Skills 是 Agent 把「與現實世界的交互過程」壓縮凝練成的可複用成功實踐，猶如孫子兵法把無數戰役壓縮成「知己知彼，百戰不殆」。Multi-Agent 的核心問題不是技術，而是**組織架構**：如何讓 Agent 之間的信息流高效流通，就像管理一家公司。

## 重點摘要

**AGI 五步路線圖現狀**

| 步驟 | 名稱 | 時間點 |
|------|------|--------|
| 1 | Chatbot | 2023 ✅ |
| 2 | Reasoner（o1 系列） | 2024 ✅ |
| **3** | **Agent**（目前位置） | **2025-2026** |
| 4 | Innovator | 3 年內 |
| 5 | Organizer | 3 年內 |
> 週亦庄判斷：AGI 可能在 2028 年前後到來

**Skills 的本質：被人類驗證的壓縮**
- MCP = Agent 與 API 的接口
- Skills = 成功實踐的壓縮（人類確認「你做的很好」→ 記錄下來 = Skills）
- 類比：孫子兵法 = 無數真實戰役的 Skills 壓縮
- Skills 是從「熟讀唐詩三百首」（知道）→「真正參與人類生產」（驗證）的轉化

**Multi-Agent 組織架構的核心問題**
- 為什麼需要組織？為了完成更遠大的目標
- 最簡單模型：一個 leader（任務編排者/調度者）+ 一群 executor
- Leader **不具體執行**，只進行計劃、發號施令、接收反饋
- 用信息論看：組織的核心 = 角色之間的信息互通

**Innovator vs Organizer（第四、五步）**
- **Innovator**：能力深度（專家標注）+ 觸手廣度（調動現實資源做實驗）→ 真正的科研者
- **Organizer**：基於願景把不同 Agent 搓合在一起 → 更像公司的 CEO
- 兩者是「你中有我，我中有你」的正交過程

**個人工作流的印證**
> 「整整一個月沒有寫過任何一行代碼，也沒有敲過任何一個命令。全都是通過和 Agent 的對話來完成我的日常工作。」——週亦庄

機制：讓模型持續更新自己的 memory，從工作中反復學習 = 持續積累 Skills

## 值得深思的問題

- 「Skills 需要人類驗證」——這個判斷對 AI 工作流設計有什麼實踐啟示？（你如何告訴 AI「你做得很好，記下來」？）
- Multi-Agent 的「組織架構」問題——對管理學有什麼反向啟示？（現有的人類組織管理理論中，哪些可以直接應用到 Agent 管理？）
- AGI 2028 預測：如果這個時間線是對的，現在應該做哪些準備？（個人層面 vs 品牌層面 vs 產業層面）
- 「觸手廣度」——Agent 能調動算力做實驗，但能調動「人情世故」嗎？有些問題的答案在人際網絡裡，不在數據庫裡。
