## 核心洞察

> AI輸出偏離預期不是AI的問題，是「上下文構建」的問題——CTX-6方法論把AI協作的核心能力從「技術門檻」轉向「表達與框架設計」，這是顧問最應該掌握的能力。

## 重點摘要

**CTX-6 六步法：**

| 步驟 | 名稱 | 核心動作 |
|------|------|---------|
| 1 | Design | 明確目標、場景、使用者 |
| 2 | Plan | 拆解為可獨立驗證的小任務 |
| 3 | **Context Build** | 三層結構：基礎信息+約束要求+參考示例 |
| 4 | Implement | 先核心功能，再補細節 |
| 5 | Test | 明確測試用例約束輸出 |
| 6 | Update Context | 沉澱成功案例為資產庫 |

**Context Flywheel（上下文飛輪）**
成功的上下文持續累積 → 後續任務越來越精準 → 開發成本持續下降

核心命題：AI時代PM的價值不在「會不會寫代碼」，而在「能否有效構建上下文系統」。

## 值得深思的問題

1. 顧問工作的「上下文」是什麼？客戶簡報、市場背景、約束條件如何系統化為「可喂給AI的結構」？個人的Context資產庫應該包含哪些元素？
2. CTX-6的「精準提問邏輯」能否轉化為教導客戶使用AI工具的簡易教學框架，成為顧問的增值服務？
3. 「Context飛輪」是個人知識積累的最佳隱喻——偷偷的Obsidian筆記庫，本身就是一個Context資產庫。如何讓它更好地服務AI協作？
