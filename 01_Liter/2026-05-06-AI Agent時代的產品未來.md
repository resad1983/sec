## 核心洞察

> 當 Agent 成為主要用戶，產品設計語言從 UI 互動轉向協議與任務，顧問方法論本身也可「Skill 化」——成為可分發、可測量、可迭代的能力單元。

## 重點摘要

| 維度 | 現在（人用） | 未來（Agent 用） |
|------|------------|--------------|
| 介面 | 操作台（讓人點） | 監控台（讓人確認） |
| API 粒度 | 動作級（單一功能） | 任務級（一件事） |
| 體驗標準 | user-friendly | agent-readable |
| 開發重心 | Feature Roadmap | Capability Roadmap |
| 驗證單位 | MVP | MVT（Minimum Viable Task） |
| 差異化來源 | 功能多寡 | Memory + Skill 積累 |

- **SaaS → SaaS 語意轉變**：Software as a Service → Service as a Software，服務業的軟體化
- **Skill 的競爭本質**：「隱性經驗的結構化能力」——什麼時候這樣做、異常怎麼判斷、優先級怎麼排
- **顧問服務的 Skill 化機會**：顧問的方法論框架、審查清單、決策流程，都可以成為可分發的 Skill
- **失去前台關係的風險**：當 Agent 替用戶選擇工具，SaaS 廠商可能失去直接用戶接觸點

## 值得深思的問題

1. **顧問視角**：偷偷的哪些顧問方法論可以「Skill 化」？能不能設計成一個可重複使用、可被 Agent 呼叫的分析框架？
2. **地方創生應用**：地方場域的服務（導覽、媒合、空間策展）如何透過「Service as a Software」的思路，把人力服務的核心邏輯數位化？
3. **系統設計視角**：「Memory 是長期差異化來源」——對顧問來說，什麼樣的知識管理系統能讓過去的累積成為難以遷移的護城河？
