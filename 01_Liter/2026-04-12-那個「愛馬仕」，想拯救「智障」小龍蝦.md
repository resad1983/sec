## 核心洞察

> Agent 落地最核心的瓶頸不是 Skill 不夠強，而是底層能調度的高品質原子工具太少——CLI 才是地基，Skill 是地基上的建築。

## 重點摘要

- **Hermes Agent**：自動把任務經驗固化為 Skill，越用越強；但遮蔽了一個更根本的問題
- **OpenClaw 的真正問題**：token 消耗大 + 穩定性差，根源是用脆弱的瀏覽器自動化替代本該由確定性工具完成的任務
- **CLI vs Skill 核心差異**：

| 維度 | CLI | Skill |
|------|-----|-------|
| 可靠性 | 確定性輸出，零 token 消耗 | 依賴模型能力，不穩定 |
| 調試難度 | 容易 | 困難 |
| 模型相依 | 不依賴 | 強依賴，換模型行為變 |
| 可遷移性 | 完全可遷移 | 「Skill 可遷移幻覺」 |

- **Claude Code 成功的秘訣**：扎實的 CLI 工具（GlobTool、GrepTool、FileReadTool、LSPTool），而非 Skill 進化

## 值得深思的問題

1. **顧問工作**：在設計 AI 工具鏈給客戶時，如何確保底層工具的確定性，而非過度依賴 LLM 的「聰明」來掩蓋工具鏈的脆弱？
2. **地方創生**：「地基不牢，Skill 再會長也只是長在沙地上」——這個比喻如何對應到地方創生中「基礎建設先行」的重要性？
3. **系統設計**：如何在 Agent 系統設計中識別哪些任務應該由 CLI（確定性）完成，哪些才需要 LLM（語言理解）？
