## 核心洞察
CLI 的本質不是黑窗口，而是「把系統能力結構化、參數化、可調用化」。釘釘與飛書的 CLI 改造不是為了讓人打字，而是為了讓 AI Agent 能以精確的動作為單位穩定執行任務，這是企業軟體從「人機交互」走向「機機交互」的關鍵基礎設施。

## 重點摘要
- **MCP 與 CLI 並非替代關係**：MCP 解決的是 N×M 工具整合的「接入層」問題（統一協議），而 CLI 解決的是能力以什麼形態被調用的「執行層」問題。兩者不在同一維度。
- **Skills 是鏈路的靈魂**：Function Calling 負責表達意圖，MCP 負責協議接入，CLI 提供執行動作，而 Skills 則負責將複雜任務（如查報銷）拆解為具體的 CLI 調用步驟，並規劃失敗後的轉彎邏輯。
- **Agent 時代的底層需求**：GUI 是為人類視覺與點擊設計的，效率上限低且難以被 AI 穩定操作；CLI 則是為機器邏輯設計的，Agent 天然需要這種可組合、確定的動作層。

## 值得深思的問題
- 在我們為傳統企業規劃 AI 轉型時，能否用這個「Function Calling + MCP + CLI + Skills」的框架，幫助他們釐清既有 IT 系統該如何改造才能真正擁抱 AI？
- 作為顧問，我自己的知識庫與工作流（如 Obsidian）是否已經足夠「CLI 化」，能被自動化腳本或 AI 穩定調用？
