## 核心洞察
Hermes Agent 的成功不在於模型本身，而在於其精密的 **「工程化判斷」**。核心設計哲學是：**用分層與權衡解決技術矛盾**。例如：用「凍結快照」解決記憶更新與緩存命中的矛盾；用「模型層壓縮+數據層完整」解決省 token 與不丟歷史的矛盾。這是一個能長期運行、持續變聰明且預算可控的實戰系統，為 2026 年的 AI 應用開發提供了標竿。

## 重點摘要
- **五層架構**：入口層 (適配器) → 網關層 (會話) → 執行層 (主循環) → 擴展層 (工具/子 Agent) → 存儲層 (記憶/數據)。
- **執行層核心邏輯**：
	- **三種退出**：正常結束、預算耗盡、用戶中斷。
	- **PTC (程序化工具調用)**：寫 Python 腳本串聯工具，免除推理輪次，大幅提升效率。
- **子 Agent 委託機制**：只傳描述，只回摘要。保持父 Agent 上下文乾淨，通過「心跳」防止主掛子不掛。
- **記憶與緩存優化**：
	- **記憶快照**：會話開始時注入提示詞，會話中不更新，以確保 100% 命中 **前綴緩存 (Prefix Cache)**。
- **自進化閉環**：後台 mini Agent 異步復盤對話，總結「非平凡方法」並沉淀為 **Skill**，實現不佔用用戶響應時間的學習。
- **上下文管理**：分層存檔，session 鏈追溯歷史，記憶工具負責主動沉淀經驗。

## 值得深思的問題
- 在我的「知識庫」建設中，哪些是「前綴緩存」級別的底層邏輯？哪些是「異步復盤」出來的實戰技能？
- 如何在不大幅增加 API 開銷的前提下，構建一套像 Hermes 一樣具備「自進步」能力的自動化工作流？
